# Session Log — 2026-08-14

## What was built
- Full-source audit of every public (unauthenticated) API route for
  free-text input risk. Only real target: newsletter signup's `name` +
  `email` (`lib/newsletter-input.ts`) — everything else public is either
  read-only/parameterized (catalog query params) or a server-generated
  token, not user-authored text.
- `lib/newsletter-input.ts`: added a 254-char email length cap (RFC 5321)
  and `stripControlChars()` (C0 controls except `\t \n \r`, plus DEL),
  applied to both `name` and `email` before trimming.
- `docs/security/prompt-injection-policy.md` (new) — the one-rule policy
  ("never include raw user-submitted text in an LLM prompt without
  explicit sanitisation"), documented as not-yet-applicable but ready for
  whenever this app adds its first LLM-backed feature.
- `docs/security/input-hardening-2026-08-14.md` (new) — audit-format doc
  recording the full route inventory, what was already safe (CSV formula
  escaping, JSON-LD script-breakout escaping, zero `dangerouslySetInnerHTML`
  in admin components), and what changed. Cross-referenced from the
  2026-07-09 OWASP audit.

## What worked
- Tracing the `name` field's every downstream use (grep, not assumption)
  before deciding what to harden — confirmed it's never used as an email
  header or interpolated into a template, which meant the real risk was
  "admin-table rendering glitches," not injection, and scoped the fix
  correctly instead of over-building.
- Manual verification with a real embedded null byte (built via Python's
  `chr(0)` + `json.dumps`, not typed literally into a shell command —
  a literal control byte in a Bash command gets blocked by the harness's
  own approval-dialog safety check) confirmed the stripped name persisted
  at the correct length in the DB.

## What drifted from intent
- Nothing — the request's own spec (exact char limits, exact control-char
  ranges, exact doc rule) left little room for drift; the main judgment
  call was confirming there's no notes/description field to apply the
  1000-char rule to, rather than inventing one.
