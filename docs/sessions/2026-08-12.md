## Friction points
- Extracting the shared `withTimeout` helper (a `/code-review` suggestion)
  introduced a nondeterministic race: when the wrapped operation also rejects
  on the same abort event (as `fetch` does), `Promise.race` had no guaranteed
  winner between that rejection and the helper's own synthetic
  `TimeoutError`. Caught immediately by the existing DYMO 504 test going red
  after the refactor — fixed by normalizing on `controller.signal.aborted`
  in a `catch` rather than trusting which promise settled first, and added a
  regression test that mocks a runner which itself rejects on abort.
- What would have prevented it: when extracting a shared timeout helper from
  two call sites, explicitly check whether the wrapped operation might race
  its *own* rejection against the timeout's synthetic one — not just "does it
  behave the same as the two originals individually."
