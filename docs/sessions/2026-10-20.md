## Retrospective

**What slowed us down this session?**
- The invisible-codepoint `Edit` failures (three failed attempts before
  finding the workaround) and the two-pass fix for the alt-text/line-break
  interaction (see "What drifted from intent").

**What should we do differently next session?**
- When a markdown-renderer regex change touches paragraph/line-break
  handling, write the test for an adjacent edge case (attribute text
  spanning the same boundary) before declaring the fix done — the
  alt-text bug would have been caught one pass earlier.

**What worked well and should be repeated?**
- Giving the code-review subagent a specific, named property to verify
  (not just "check this is safe") produced a much sharper, actionable
  finding than a generic review prompt would have.
- Visual browser verification both before AND after the review fixes,
  rather than trusting the test suite alone for a UI-facing rendering
  change.
