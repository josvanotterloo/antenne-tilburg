## Friction points
- Browser automation coordinates went stale across screenshots taken at
  different points in the same page (a click based on an earlier screenshot's
  layout silently landed on the wrong element, with no error — the typed text
  just went nowhere). Switching to `ref`-based clicks from `read_page`/`find`
  instead of raw coordinates fixed it immediately. Next time: prefer `ref`
  clicks by default for form fields, reserve coordinate clicks for one-shot
  interactions right after a fresh screenshot.
- A pre-existing `next dev` server from an earlier session was running on
  port 3000 with a stale Prisma client (predating today's migration). Had to
  stop and ask before killing a process I didn't start this session, per the
  standing lesson about `pkill`/broad process management.

## Retrospective

**What slowed us down this session?**
- The browser coordinate-staleness issue above cost a few retries before
  switching to ref-based clicking.

**What should we do differently next session?**
- Default to `read_page`/`find` + ref-based clicks for any multi-step form
  fill in the browser, not just when coordinate clicks visibly fail.

**What worked well and should be repeated?**
- Full context-gathering (all referenced files, plus tracing every call site
  of `joinArtistNames` before responding to the code-review finding about
  incomplete rollout) before writing the plan and before accepting/rejecting
  review findings.
- Asking the user a scoped, single-question AskUserQuestion for the one
  genuinely-open call (shelf label contents) rather than silently expanding
  scope or silently ignoring the finding.
