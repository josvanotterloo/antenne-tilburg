## Code review
- Code review: run — 4 findings. 3 fixed: `hasUnsentPending` had no 48h age
  cutoff (retry button could stay visible for a row the retry endpoint would
  silently skip — extracted `lib/newsletter-confirm-window.ts`'s
  `isRetryEligible()`, shared by the button-visibility check and the confirm
  route too, now 3 call sites agreeing on one constant instead of 2 disagreeing
  ones); the migration had no backfill for pre-existing PENDING rows (would
  have caused the retry queue to duplicate-email every already-pending
  subscriber on first run — added an `UPDATE ... WHERE status = 'PENDING'`
  backfill, cleanly re-applied since the migration was still local-only);
  a DB write failure after a successful send was miscounted as "failed"
  (separated the send-success count from the best-effort confirmEmailSentAt
  write). Pushed back on 1 (sequential vs. concurrent sends in the retry
  loop — small expected volume, and concurrency risks tripping Resend's rate
  limit for no real benefit here; documented as an accepted limitation
  instead).
